# Handover: GitHub PR hover cards in the chat

Moved from `hairline/.claude/handover-pr-cards.md` on 2026-11-18. Open question 4 is decided: PR cards live in this separate plugin, `pr-cards`. The hairline paths, version and repo rules below describe hairline. The rules for this repo are in `AGENTS.md`.

Goal: in the Claude Code transcript, a reference such as `PR #1234` is drawn as a chip. Hovering the chip shows a card with the title, author, state, checks, reviewers and a link. Holding Alt keeps the card open so the pointer can move into it and click the link. Terminal first (Windows Terminal), desktop app later. Several PRs, from several repos, in one session.

Status: not started. No branch, no code. This file is the only artifact.

## The mod API supports it

Source: `.claude-plugin/types/claude-code/index.d.ts` (generated by `claude --plugin-dir .`, gitignored, 17,305 lines on 2026-11-18).

- `ui.render` with `component: 'AssistantMessage'` (line ~10485) gives `text` (the block's markdown). A hook returns its own tree. The stored message stays unchanged, and ctrl+o still shows the original.
- `component: 'UserMessage'` works the same way for the user's own prompts ("ok i have reviewed PR #1234").
- `BoxProps.hover` (line ~880 to 960): a keyed `Box` holding a `position: "absolute"` Box drawn `display: "none"` with `hover: { display: 'flex' }` shows a card while the pointer is over it. No hook runs, and siblings do not move. The types include this example:
  `<Box key="k"><Text>glyph</Text><Box position="absolute" top={-2} left={2} display="none" hover={{ display: 'flex' }}>the card</Box></Box>`
- `BoxHoverProps.scope` connects a mark on a transcript message to a Pane row, so the same card could also appear in a side Pane.
- `Link` (line ~5862) is drawn as OSC 8 in the terminal and as an anchor in the desktop app.
- `Markdown` (line ~5895) draws text the way an assistant reply is drawn. With `onLinkPress` and a `key`, a click on a link raises `ui.press`.
- `ClientPointerEvent` (line ~1486) reports `enter`, `leave`, `down`, `move` and `up`, with `alt`, `ctrl` and `shift` flags. This only works inside a Client module (`surface.onPointer`), as `hooks/chip.tsx` already does.

## Proposed design

1. Detection: a regex over `AssistantMessage.text` and `UserMessage.text` finds `#1234`, `owner/repo#1234` and `https://github.com/owner/repo/pull/1234`. A bare `#1234` resolves to the repo of the session cwd (`git remote get-url origin` through `$.process`).
2. Data: `gh pr view <n> --repo <owner/repo> --json number,title,author,state,isDraft,reviewDecision,statusCheckRollup,reviews,url,additions,deletions,changedFiles` through `$.process`. Results are cached in `$.store` with a TTL of about 60 s. On a cache miss, the chip is drawn first and `$.ui.invalidate('ui.render')` redraws it once the data arrives.
3. Drawing: the block is split at each match. Text between matches is drawn with `Markdown`. Each match becomes a keyed Box: the chip text plus an absolute card that appears on hover. Splitting a paragraph breaks its inline flow, because `Markdown` is a leaf element (open question 1).
4. Alt to pin: hover props cannot react to Alt, because no hook runs. Pinning needs the chip to be a Client module, a sibling of `chip.tsx`. `onPointer` with `alt` sets `pinned` in `surface.state`, and the card then draws with `display: 'flex'` until the pointer leaves the card.
5. Click: a `Link` to the PR URL inside the card. Ctrl+click opens it in Windows Terminal.

## Open questions, in order

1. Inline flow. Can a Box chip sit inside a paragraph, or does each PR reference need its own row? Test it on the screen. The fallback is to keep the `Markdown` block and draw one row of PR chips under it.
2. Alt in Windows Terminal. Mouse reports carry Alt as the meta bit, and Windows Terminal may use Alt+drag for block selection. Check that `e.alt` actually arrives. If it does not, pin on click (`down` then `up`).
3. Card position near the viewport edge. An absolute Box is clipped by its site. `top={-n}` above the chip may be cut off on the first row.
4. Scope. Hairline is a status line mod (`plugin.json` description). Decide whether PR cards go into hairline or into a separate plugin in the same marketplace. A separate plugin keeps `claude plugin test .` and the README for hairline focused on the status line.

## Repo rules that apply (from AGENTS.md)

- `hooks/hooks.json` loads only `register.tsx`. Client modules (the new PR chip) stay out of it.
- Register `ui.render` once per matcher. Hairline already hooks `ui.render` for `PromptHint` and `AbovePrompt`, so add `{ component: 'AssistantMessage' }` and `{ component: 'UserMessage' }` matchers.
- Do not use `import()`, `require`, Node or the DOM. Use `$.process`, `$.http`, `$.store` and `$.clock`.
- Colors come from `ansi256(n)` with n below 16 in the terminal. Never use hex.
- Source files are CRLF. Use Conventional Commits, one PR per change, and bump `.claude-plugin/plugin.json` (now 0.45.0).
- Check with `claude plugin validate .` and `claude plugin test .`. Tests can mock `$.process` and `http.fetch` (see `tests/hairline.test.ts`).
- The Pi port (`pi/`) does not get this feature, because Pi has no transcript render hook. Say so in the PR.
