# AGENTS.md

pullywog (named pr-cards before 0.8.0) is a Claude Code mod and a Pi extension. It draws GitHub pull request references in the transcript as chips, with a hover card per PR, and keeps tracked PRs in a band above the prompt. The design and open questions are in `docs/handover.md`.

## Feature parity: the first rule

pullywog does the same in every agent it supports: Claude Code (`hooks/`) and Pi (`pi/`). A change to what it shows or does lands in both in the same PR, with tests in each. A PR that changes one agent alone does not merge. A host that cannot do a feature at all is the only exception, and the PR names the missing host API. Pi 1.6.0 has no mouse hook inside the transcript: `pi/pointer.ts` reads the mouse reports from stdin instead, so the hover card and the click that tracks a reference work in both.

## Check

```sh
claude plugin validate .
claude plugin test .
```

CI runs both on Claude Code 2.1.327 (Node 22). Raise the pin only on purpose, because the mod API can change between releases.

## Hooks

- `hooks/hooks.json` loads `hooks/register.tsx` only. Client modules (the Alt-to-pin chip) stay out of it.
- Register each event once, or each time with its own matcher. A second `on` of the same event without one throws.
- No `import()`, `require`, Node or DOM. Use `$.process`, `$.http`, `$.store` and `$.clock`.
- Colors come from `ansi256(n)` with n below 16 on the terminal, or theme keys elsewhere. Never hex.

## Pi

- `pi/index.ts` is the Pi extension, loaded through `pi.extensions` in `package.json`. It draws the band with `ctx.ui.setWidget` above the editor, the dots with `pi.registerMarkdownTransformer`, and takes the keyboard with `ctx.ui.custom` on `Alt+A`.
- `pi/prs.ts` holds what needs no Pi host: finding references, the query, the tracked list and the band's lines. `pi/card.ts` draws the hover card. Both run under `node --test` as they are.
- `pi/pointer.ts` reads SGR mouse reports from `process.stdin` beside Pi's own reader, because Pi's fullscreen mode takes them before `onTerminalInput`. It finds the reference under the pointer in `TuiAltScreen.getScreenLines()` and shows the card with `tui.showOverlay({ nonCapturing: true })`. References in replies stay text, not links: Pi opens a link on any click.
- Pi tests live in `pi/tests.ts`. A `*.test.ts` name would make `claude plugin test` run them with the Claude Code test kit.
- Check with `npm ci`, `npm run typecheck:pi` and `npm run test:pi`. CI runs them after the Claude Code steps. `scripts/pi-e2e.py` drives a real Pi session.
- Bump `version` in `package.json` with the one in `plugin.json`.
- The Pi extension is on npm as `@accodev/pullywog`. A published GitHub release runs `publish.yml`, which stages the version through npm trusted publishing; a maintainer approves it with 2FA on npmjs.com. After the approval, check that the `latest` dist-tag points at the new version.

## Types

`.claude-plugin/types` is generated by `claude --plugin-dir .` in an interactive session and gitignored. Do not edit or commit it.

## Ship

- Conventional Commits. One PR per change, CI green, rebase merge.
- Bump `version` in `.claude-plugin/plugin.json` on a behavior change.
- Tag each release with `claude plugin tag --push`, which makes `pullywog--v<version>`. Install and update read these tags to give an older Claude Code the newest version that fits its `engines` range.
- Raise `engines["claude-code"]` in `plugin.json` only when a release needs a newer build for the whole plugin. Keep it out of `marketplace.json`: Claude Code 2.0.15 to 2.1.75 reject a marketplace whose entry has it.
- A feature on a newer API switches itself off on older builds. Wrap a new `$` call in try/catch, because a missing call throws a TypeError where it is made. Hook a new event through a pattern such as `prompt.*` and test `next.event`, because an unknown event name refuses the whole module.
- README images come from `scripts/screenshots.mjs`, which draws fixed scenes with `pi/prs.ts` and `pi/card.ts` on made-up repos and people. The `screenshots` workflow renders them on `main` and pushes them to the `screenshots` branch. No real repo, PR or person goes into an image.
- Comments say why, never what.
- Source files and `plugin.json` are CRLF. Other JSON, YAML and Markdown files are LF.
